# V0.4 — ADMET evidence + uncertainty

V0.4 replaces heuristic CNS/drug-likeness proxies with **separately benchmarked molecular-property models**. It deliberately does **not** collapse BBB, toxicity and solubility into a single hidden score.

## Endpoints

| Endpoint | Task | Public benchmark | Output |
|---|---|---|---|
| BBBP | binary classification | MoleculeNet BBBP / Martins et al. | calibrated penetration probability + entropy + applicability domain |
| ClinTox | binary classification | MoleculeNet ClinTox (`CT_TOX`) | calibrated toxicity probability + entropy + applicability domain |
| ESOL | regression | Delaney ESOL / MoleculeNet | predicted logS + validation-calibrated 90% residual interval + applicability domain |

References:

- MoleculeNet: `doi:10.1039/C7SC02664A`
- BBBP source study: `doi:10.1021/ci300124c`
- ESOL: `doi:10.1021/ci034243x`

These are benchmark endpoints, **not experimental validation of a Parkinson candidate**.

## Scientific contract

1. Canonical SMILES are the modelling unit.
2. Conflicting duplicate classification labels are discarded rather than averaged into fake certainty.
3. Whole Bemis–Murcko scaffolds stay together.
4. Model family selection uses validation scaffolds only.
5. Classification probabilities are Platt-calibrated using validation scaffolds.
6. Regression intervals use the 90th percentile of absolute validation residuals.
7. Test scaffolds remain untouched until final endpoint evaluation.
8. Every prediction includes maximum Morgan/Tanimoto similarity to the endpoint training chemistry.
9. `high/moderate/low_similarity` is a descriptive heuristic, not a universal medicinal-chemistry threshold.
10. Endpoint outputs remain separate; V0.4 does not manufacture a single “drug probability”.

## Fetch public datasets

```bash
pdl admet-fetch --dataset bbbp
pdl admet-fetch --dataset clintox
pdl admet-fetch --dataset esol
```

Each download writes a `.source.json` sidecar containing the URL and SHA-256 hash.

## Train endpoint models

```bash
pdl admet-train \
  --dataset bbbp \
  --input data/admet/bbbp.csv \
  --out artifacts/admet/bbbp

pdl admet-train \
  --dataset clintox \
  --input data/admet/clintox.csv.gz \
  --out artifacts/admet/clintox

pdl admet-train \
  --dataset esol \
  --input data/admet/esol.csv \
  --out artifacts/admet/esol
```

Each endpoint directory contains:

```text
endpoint_prepared.csv
metrics.json
model.joblib
manifest.json
```

The manifest hashes the artifacts and records the environment, source file hash, model, split seed and endpoint dataset contract.

## Annotate LRRK2 candidates

After the V0.3 LRRK2 run:

```bash
pdl admet-annotate \
  --input artifacts/lrrk2_v03/ranked_candidates.csv \
  --models artifacts/admet \
  --out artifacts/lrrk2_v04/candidates_admet.csv
```

Example columns:

```text
bbbp_probability
bbbp_predictive_entropy
bbbp_ad_similarity
bbbp_ad_band
clintox_probability
clintox_predictive_entropy
clintox_ad_similarity
clintox_ad_band
esol_prediction
esol_pi90_low
esol_pi90_high
esol_ad_similarity
esol_ad_band
admet_low_similarity_endpoints
```

Interpretation is endpoint-specific. A high BBB probability does not imply efficacy. A low ClinTox model probability does not establish safety. ESOL is only one piece of developability.

## V0.4 definition of done

V0.4 software is complete when:

- BBBP, ClinTox and ESOL adapters work on their public benchmark files;
- classification calibration and regression intervals are evaluated on held-out scaffolds;
- applicability-domain evidence is attached to every candidate prediction;
- endpoint manifests make results reproducible;
- LRRK2 candidates can be annotated without changing the original activity ranking;
- CI passes.

The next scientific run is to execute these benchmark downloads and record the **real** held-out metrics. Those numbers must not be invented from the synthetic test suite.
